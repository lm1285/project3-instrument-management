## 现代化目标

### 1. 前端目标

- 大组件只负责装配和状态拼接，不直接承载长段纯业务逻辑
- 统一表格、筛选、导入、批量操作的交互模式
- 逐步收敛为“页面组件 + hooks + utils + 子组件”的稳定结构
- 减少重复定义的常量、筛选项和状态转换逻辑

### 2. 后端目标

- 路由层只做参数校验和响应拼装
- 服务层拆分为调度核心、查询组装、冲突分析、持久化操作四类模块
- 降低单文件长度，减少“一个服务文件包办所有逻辑”的维护成本
- 为关键调度逻辑补充可独立验证的纯函数入口

### 3. 工程目标

- 每轮修改都保留 lint/build/Python 校验闭环
- 优先抽离纯函数与共享常量，避免先做高风险行为改动
- 在结构优化后，再考虑性能优化和缓存策略
